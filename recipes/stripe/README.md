# Stripe recipe

What the script assumes, and the Stripe page each assumption comes from (read 2026-11-17).

- **Signature.** The `Stripe-Signature` header is `t=<unix>,v1=<hex HMAC-SHA256 of "t.body">`, signed with the endpoint's `whsec_` secret, with a 5-minute tolerance. Source: [Check the webhook signatures](https://docs.stripe.com/webhooks/signature).
- **Resends.** Stripe retries an event with the same event `id`, so the recipe ignores a second delivery with the same `id`. Source: [Webhooks: handle duplicate events](https://docs.stripe.com/webhooks).
- **Orders.** `checkout.session.completed` "occurs when a Checkout Session has been successfully completed". For delayed payment methods the session's `payment_status` is not `paid` yet, and `checkout.session.async_payment_succeeded` follows when the payment succeeds. The order is recorded on whichever arrives paid, keyed by the Checkout Session id, so it counts once. Sources: [Fulfill orders](https://docs.stripe.com/checkout/fulfillment) and [Event types](https://docs.stripe.com/api/events/types).
- **Subscription invoices.** `invoice.paid` uses `customer_email`, `amount_paid`, `billing_reason` and the subscription id (`subscription`, or `parent.subscription_details.subscription` in newer API versions). Source: [The Invoice object](https://docs.stripe.com/api/invoices/object).
- **Refunds.** `charge.refunded` "occurs whenever a charge is refunded, including partial refunds. Listen to `refund.created` for information about the refund." A charge's `amount_refunded` is a running total. So each refund is recorded once from `refund.created`, by its refund id, with that refund's own `amount`. When a `charge.refunded` payload lists its refunds (`refunds.data`, as older API versions do), those are recorded under the same ids, so nothing counts twice. Sources: [Event types](https://docs.stripe.com/api/events/types) and [The Refund object](https://docs.stripe.com/api/refunds/object).
- **Refund attribution.** A refund carries `customer` but no email, so it is matched to the profile through the saved `stripe_customer_id`. A refund of a guest checkout (no Stripe customer) can't be matched and is logged, unless its `charge.refunded` lists the refund.
- **Subscriptions.** `customer.subscription.created` and `.deleted` carry the customer id but no email. When that customer isn't known yet (their first invoice is still on its way), the delivery fails and is retried with backoff (1, 5, 30 and 120 minutes). Source: [The Subscription object](https://docs.stripe.com/api/subscriptions/object).
- **Consent.** A customer is subscribed only when `consent.promotions` is `opt_in` (Checkout's promotional emails checkbox). Source: [Collect consent for promotional emails](https://docs.stripe.com/payments/checkout/promotional-emails-consent).
- **Amounts.** Amounts are in the smallest currency unit, except zero-decimal currencies (JPY, KRW, …). Source: [Zero-decimal currencies](https://docs.stripe.com/currencies#zero-decimal).
