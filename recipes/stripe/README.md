# Stripe recipe

What the script assumes, and the Stripe page each assumption comes from (read 2026-11-17).

- **Signature.** The `Stripe-Signature` header is `t=<unix>,v1=<hex HMAC-SHA256 of "t.body">`, signed with the endpoint's `whsec_` secret, with a 5-minute tolerance. Source: [Check the webhook signatures](https://docs.stripe.com/webhooks/signature).
- **Resends.** Stripe retries an event with the same event `id`, so the recipe ignores a second delivery with the same `id`. Source: [Webhooks: handle duplicate events](https://docs.stripe.com/webhooks).
- **Orders.** `checkout.session.completed` "occurs when a Checkout Session has been successfully completed". For delayed payment methods the session's `payment_status` is not `paid` yet, and `checkout.session.async_payment_succeeded` follows when the payment succeeds. The order is recorded on whichever arrives paid, keyed by the Checkout Session id, so it counts once. A session whose `payment_status` is `no_payment_required` (free, or fully discounted) took no money and isn't an order; the buyer's profile is still updated. Sources: [Fulfill orders](https://docs.stripe.com/checkout/fulfillment), [The Checkout Session object](https://docs.stripe.com/api/checkout/sessions/object) and [Event types](https://docs.stripe.com/api/events/types).
- **Subscription invoices.** `invoice.paid` uses `customer_email`, `amount_paid`, `billing_reason` and the subscription id (`subscription`, or `parent.subscription_details.subscription` in newer API versions). Source: [The Invoice object](https://docs.stripe.com/api/invoices/object).
- **Refunds.** A Refund's `status` is `pending`, `requires_action`, `succeeded`, `failed` or `canceled`, and `refund.updated` reports changes. So a refund is recorded only once it has `succeeded` (from `refund.created` when it is already there, or from the `refund.updated` that gets it there), once per refund id, with that refund's own `amount`. `charge.refunded` "occurs whenever a charge is refunded, including partial refunds", and a charge's `amount_refunded` is a running total, so it's never used as an amount; when a `charge.refunded` payload lists its refunds (`refunds.data`, older API versions), the succeeded ones are recorded under the same refund ids, so nothing counts twice. Sources: [The Refund object](https://docs.stripe.com/api/refunds/object) and [Event types](https://docs.stripe.com/api/events/types).
- **Refund attribution.** A Refund has no email, and its `customer` is nullable (usually empty). It names its `payment_intent` and `charge` (unexpanded ids). Each payment's PaymentIntent and charge ids are saved on the buyer's profile as keys (from the Checkout Session's `payment_intent`, the invoice's `payment_intent` or `payments`, and `charge.refunded`), and the refund finds the buyer by its PaymentIntent, else its charge, else its customer. When the payment hasn't arrived yet, the delivery is retried. Sources: [The Refund object](https://docs.stripe.com/api/refunds/object) and [The Invoice object](https://docs.stripe.com/api/invoices/object).
- **Subscriptions.** `customer.subscription.created` and `.deleted` carry the customer id but no email. A subscription created with status `incomplete` (its first payment hasn't gone through) hasn't started: the start is recorded when it is `active` or `trialing`, from `.created`, or from the `customer.subscription.updated` whose `previous_attributes.status` was something else, or from its first paid invoice. All three use the key `stripe:subscription:<id>:started`, so the start counts once. When the customer isn't known yet (their first invoice is still on its way), the delivery fails and is retried with backoff (1, 5, 30 and 120 minutes). Sources: [The Subscription object](https://docs.stripe.com/api/subscriptions/object) and [Event types](https://docs.stripe.com/api/events/types).
- **Consent.** A customer is subscribed only when `consent.promotions` is `opt_in` (Checkout's promotional emails checkbox). Source: [Collect consent for promotional emails](https://docs.stripe.com/payments/checkout/promotional-emails-consent).
- **Amounts.** Amounts are in the smallest currency unit, except zero-decimal currencies (JPY, KRW, …). Source: [Zero-decimal currencies](https://docs.stripe.com/currencies#zero-decimal).
